# Phase 2：真实用户痛点映射

> 痛点来源：项目设计者真实跟车约一周的观察（家人跑卡车）。逐项分析：软件/AI 能解决什么、不该解决什么、MVP 值不值得做。

## 痛点 1：长途吃饭困难

- **问题**：长途运输途中没有合适餐馆、不方便随时停车。
- **真实场景**：吃泡面、用暖壶接热水、服务区用卡式炉做饭、车上带便携冰箱、从家带冷冻饺子。
- **用户损失**：饮食不规律伤身体、临时找吃的时间成本高、吃不好影响驾驶状态。
- **软件能解决什么**：结合"当前路线 + 预计到达时间 + 服务区位置 + 停车条件 + 休息时间窗 + 车上已有食品"提前生成补给计划；标记哪些服务区能接热水、能停车、有餐饮。
- **AI 能解决什么**：把上述结构化数据变成人话建议（"今晚 7 点前后经过 XX 服务区，有热水和停车位，建议在那吃饭"）。
- **AI 不应该解决什么**：不能自己编服务区位置/营业时间（必须来自地图 POI 数据）；不能做营养/医疗诊断。
- **MVP 是否值得做**：**P5/P6 阶段做**（依赖运输执行闭环先跑通）。第一版只做"服务区提醒"，不做冰箱/食材管理。

## 痛点 2：装货沟通困难

- **问题**：到达装货地点后沟通难。
- **真实场景**：去杭州拉电梯时，不知道从哪个入口进、大货车停车位不好找、停车反复调整、司机和装货方都着急。
- **用户损失**：时间浪费、双方焦虑、可能被投诉、错过装货窗口。
- **软件能解决什么**：订单执行信息结构化——装货地址、货车入口、联系人、联系电话、装货时间、停车区域、特殊注意事项、**卡友历史经验**（前一个司机怎么进的、停哪）。
- **AI 能解决什么**：把卡友反馈总结成"装货指引摘要"；回答司机"这个厂怎么进"（基于结构化反馈，不是编造）。
- **AI 不应该解决什么**：不能自己编入口/停车位（必须来自运营确认 + 卡友反馈）；不能代替电话沟通。
- **MVP 是否值得做**：**P2 运营闭环必做**——这是"司机付 200 元后平台提供的核心价值"之一。

## 痛点 3：车载网络不稳定

- **问题**：车载移动 Wi-Fi 有流量限制、超套餐限速、长途网络不稳。
- **真实场景**：长途到山区/偏远路段断网，订单信息、导航、导航缓存受限。
- **用户损失**：断网时无法接单/看订单/联系平台；可能错过关键通知。
- **软件能解决什么**：出车准备提醒（当前剩余流量、预计行程时间、建议提前下载离线地图、保留流量给导航和订单通信）；关键订单信息本地缓存（离线可看）。
- **AI 能解决什么**：几乎没有——最多把"流量 + 行程"数据汇总成一句提醒。**这不是 AI 场景。**
- **AI 不应该解决什么**：不读运营商/硬件数据（MVP 明确不做真实运营商接入）。
- **MVP 是否值得做**：**P5 之后**，且第一版只做"手动填写剩余流量 + 提醒"，不做真实运营商控制。

## 痛点 4：司机安全（疲劳/独处风险）

- **问题**：长时间驾驶、休息不足、独自睡在货车卧铺、突发情况无人知晓。
- **真实场景**：司机独自出车，若夜间突发疾病/意外，家人和平台都不知道。
- **用户损失**：人身安全风险（最高优先级痛点）。
- **软件能解决什么**：安全守护第一版——长时间未响应 → App 提醒 → 司机确认状态 → 持续无响应 → 按司机预设的应急联系人/流程升级；紧急时一键联系当地紧急服务。
- **AI 能解决什么**：几乎没有。**AI 不做医疗诊断、不擅自报警。**
- **AI 不应该解决什么**：医疗诊断、自动报警决策、健康数据编造。
- **MVP 是否值得做**：**P6 必做**，但第一版只做"定时确认 + 联系人升级"，边界清晰、风险低。

## 痛点 5：货源可靠性（平台信息 ≠ 实际情况）

- **问题**：平台显示的货源信息不一定等于实际情况（假货源、压价、信息过期、装货点刁难）。
- **真实场景**：司机接到一单，到了才发现价格不对、货不对板、联系不上人；司机最终靠自己的行业经验 + 人脉验证。
- **用户损失**：空驶损失、时间损失、被欺诈风险（本痛点直接决定"司机敢不敢用这个平台"）。
- **软件能解决什么**：**货源可信度体系**——平台客观数据（信息完整度、更新时间、价格区间对比）+ 运营人工确认（打电话核实）+ 历史成交数据 + 卡友结构化反馈（装货等待时长、装卸难易）+ 货主信用分 → 汇总成可信度分与风险提示。
- **AI 能解决什么**：把可信度证据链汇总成解释（"91 分：已认证 ✓ 运营确认 ✓ 历史成交 ✓；⚠ 2 名司机反馈装货等待长"）；风险说明。**AI 只分析证据，不凭空判定真假。**
- **AI 不应该解决什么**：不能"凭感觉判断货源真假"；不能编造验证记录。
- **MVP 是否值得做**：**P1/P2 最优先**——这是产品的核心差异化和信任基础。

## 六、痛点优先级结论

| 痛点 | 优先级 | 阶段 | 核心形态 |
|---|---|---|---|
| 货源可靠性 | 最高 | P1–P2 | 可信度分 + 运营审核 + 卡友反馈 |
| 装货沟通 | 高 | P2 | 订单执行信息 + 卡友经验 |
| 司机安全 | 高 | P6 | 定时确认 + 联系人升级（不做医疗/自动报警） |
| 吃饭困难 | 中 | P5–P6 | 服务区补给提醒（基于地图数据） |
| 网络 | 低 | P6+ | 手动流量填写 + 提醒（不做运营商接入） |
