# Phase 3：角色与权限模型

> 现状：auth 只区分"登录与否"，**没有角色模型**。V2 引入四类角色。数据权限 = 谁能看到谁的什么数据。

## 一、四类角色总览

| 角色 | 核心目标 | 一句话 |
|---|---|---|
| 货源发布方（货主/物流公司/车队/中介） | 让货被靠谱司机拉走 | 发货 |
| 平台运营 | 让每一单真实、可控、可追溯 | 审核与护航（**不是普通 Admin**） |
| 卡车司机 | 找到值得跑的货并安全跑完 | 核心用户 |
| 运输需求客户 | 找到运力把货按时送到 | 找车 |

## 二、货源发布方

- **核心目标**：发布真实货源，找到匹配且靠谱的司机，货物按时安全送达。
- **主要权限**：发布货源、填写货物信息（品名/大类/重量/车型要求）、起点/终点、装货时间、卸货时间、运费、维护货源状态（撤销/已成交）；查看本货源的承运司机与运输进度。
- **数据权限**：只看自己发布的货源与关联订单；看不到其他货主货源、看不到司机完整档案（只看到车型/车牌/信用摘要）。
- **关键操作**：发布货源 → 接运营电话核实 → 确认承运司机 → 装货/卸货配合 → 确认回单 → 结算运费 → 评价司机。
- **现状**：❌ 没有此角色。PostCargo（手动发单）目前是"司机互助发单"，语义上是车队互助，不是货主端。

## 三、平台运营人员（重点，不是普通 Admin）

- **核心目标**：让每一单货**真实、信息准确、过程可控、异常有人管**。运营是平台"服务费价值"的执行者。
- **主要权限**：
  - 审核货源（联系货主电话核实信息 → 标记"运营已确认"）
  - 维护货源（补全装货地址/货车入口/联系人/停车区域/注意事项）
  - 对接司机（接单后主动联系司机，确认装货/卸货信息）
  - 处理订单异常（货不对板、联系不上、装卸纠纷）
  - 处理司机与货主沟通（居中协调）
  - 维护订单状态（推动 8 步证据链完成）
  - 记录验证结果（每次电话核实留痕 = OperationRecord）
  - 处理卡友反馈（审核反馈真实性，归档为可信度证据）
  - 查看订单证据链（纠纷时调取证据包）
- **数据权限**：可看全平台货源/订单/证据链/反馈；**看不到**用户密码、司机完整隐私（如身份证全号，仅脱敏）；所有敏感操作必须留痕（谁、何时、改了什么）。
- **关键操作**：审核货源 → 打电话核实 → 确认承运 → 介入异常 → 归档证据 → 评价交易主体。
- **现状**：❌ 完全不存在。V2 需要单独的运营端（Web 管理台）。

## 四、卡车司机（核心用户）

- **核心目标**：找到"值得跑"的货（净收益/每公里/风险可控），安全完成运输，积累信用与证据。
- **主要权限**：
  - 注册/登录、完善车辆信息（车型/油耗/油价/载重/杂费）、设置司机底线（最低每公里净收益/最低单趟净收益/最大运距/路线偏好）
  - 搜索货源、查看详情、查看平台客观数据与可信度、查看历史、查看卡友反馈
  - 询问 AI（需求解析/推荐解释/风险说明）
  - 运输收益分析 → 决定是否承运
  - 支付平台服务费（MVP 用虚拟服务额度，不可提现/转账）
  - 进入运输执行流程（装货/运输/卸货/上传凭证/完成订单）
  - 反馈实际运输情况（货主评价 + 卡友反馈：装货等待、装卸难易、入口信息）
  - 设置应急联系人（安全守护）
- **数据权限**：只看货源与自己的订单/账本/信用记录；看不到其他司机信息（除非通过卡友反馈的匿名聚合）；看不到货主完整联系方式——**支付服务费前只能看到脱敏联系方式，支付后由运营对接**。
- **现状**：🟡 大部分已有（底线/搜索/详情/AI/分析/接单/证据链/反馈），缺：服务费、运营对接、安全联系人。

## 五、运输需求客户

- **核心目标**：发布运输需求，找到合适运力，全程看到运输状态，货物按时送达。
- **主要权限**：发布需求、搜索运输资源、查看司机/车辆信息（脱敏）、查看报价、选择司机、查看运输状态、完成运输确认。
- **数据权限**：只看自己的需求与关联运输；看不到其他客户；看不到司机手机号（通过平台联系）。
- **关键操作**：发布需求 → 收报价 → 选司机 → 跟踪状态 → 确认送达 → 评价。
- **现状**：❌ 没有。**V2 定位**：当前代码里没有客户角色，但产品定位说"如果已有客户相关角色请保留"——经查**没有**，故 P3 阶段补（最低优先级，货主端先做）。

## 六、权限模型落地建议

1. `User` 表增加 `role` 字段（driver / shipper / ops / customer）+ 每角色专属档案表。
2. session token 携带角色声明，后端中间件做角色级路由守卫（司机端 API / 运营端 API / 货主端 API 分开）。
3. 运营端所有写操作写 `OperationRecord`（谁/何时/何操作/前后值），满足"留痕"要求。
4. 敏感字段脱敏规则集中管理（司机手机号、货主联系方式在"支付服务费/运营对接"前只展示脱敏版）。
