# 货运雷达 · 验收标准

> 版本 **v1.0**（2026-10-29）｜适用对象：本项目「货运雷达」的每个阶段收尾、每次上线、每日自动化收尾与面试演示前自检。
> 分工：**AGENTS.md** 讲「怎么改才不闯祸」，**README** 讲「产品是什么 / 怎么用」，**本文件**讲「什么算做完、拿什么证明」。
> 本文所有数字均为 2026-10-29 在本机（Node v25.2.0、Windows、Mock + 规则引擎）实测值，复测日期一变就重测并改日期。

## 0. 判定规则（先看这一节）

| 术语 | 含义 |
| --- | --- |
| **MUST** | 必须通过；任一条不过 = 本轮验收不通过 |
| **SHOULD** | 应当通过；不过必须书面记录原因、影响与补齐期限 |
| **基线** | 2026-10-29 实测值（见 §9）；验收时允许在基线 2 倍内波动，超过要解释 |
| **一票否决** | 见 §8，命中任一条直接判不通过，不进入下一阶段 |

**验收结论只能有三种**：

1. **通过**——全部 MUST 通过；SHOULD 未过项已记录并承诺期限。
2. **有条件通过**——仅个别 SHOULD 未过，且不涉及金额、安全、数据一致性。
3. **不通过**——任一 MUST 未过，或任一票否决项命中。

> 铁律：**「测试全绿」只是第一层**。自动化门通过 ≠ 项目验收通过；金额、AI 边界、数据一致性必须按 §3 手算/抽查。

## 1. 角色、时机与交付物

- **验收人**：开发自验（§2 自动化门 + §3 功能）＋ 模拟司机视角（UAT 场景）＋ 上线前安全复核（§6）。
- **时机**：每个阶段收尾 / 每次推送前 / 公网演示发布前 / 每日自动化任务收尾 / 面试演示前。
- **必交交付物**（缺一项即 MUST 未过）：
  - 代码：`main` 分支，且 `gitee/main` 远端哈希 = 本地 HEAD；
  - 构建产物：`dist/`（后端）与 `web/dist/`（前端）能由命令重建；
  - 文档：`README.md`、`AGENTS.md`、`deploy/免责声明.txt` 与实现一致；
  - 运行实例：本地一键启动可访问，或公网演示链接可访问；
  - 验收记录：按 §12 模板落一条（本次验收的证据与遗留项）。

## 3. 功能验收（UAT，司机视角）

> 全部用 Mock + 规则引擎也能跑；带 `LLM` 标记的项需要配置真实 `DEEPSEEK_API_KEY` 才有意义。

### 3.1 核心决策闭环

| 编号 | 场景 | 操作 | 通过判定 | 级别 |
| --- | --- | --- | --- | --- |
| UAT-01 | 服务健康 | `curl.exe -s localhost:3000/api/health` | 200，`{ok:true,name:"货运雷达"}` | MUST |
| UAT-02 | 首页聚合 | 打开 `http://localhost:3000/`，看首页 | 今日/本月收益、Top 推荐、回程货数、订单数都有值；无数据时显示空态而非崩溃 | MUST |
| UAT-03 | 一句话找货 | `POST /api/assistant`，body：`{"text":"帮我看看从临沂回临汾的黄豆粕，每公里不低于3块"}` | `parsed=true`，`query` 含 `from:临沂 to:临汾 cargo:黄豆粕 minPerKm:3`；`scored` 条数 ≤ `topN`；解释文案中的净收益/每公里与该单 `cost` **完全一致**（抽查 1 条手算） | MUST |
| UAT-04 | 同类口径一致 | 同一货源（如 `DEMO2`）分别取 `/api/cargos`、`/api/cargos/:id`、`/api/dashboard`、`/api/assistant` 的 `cost.netIncome` / `perKm` | 四处金额误差 ≤ 0.01（已回归：`DEMO2` 均为 `emptyCost=0` / `net=3777.44` / `perKm=5.9` / `total=90`） | MUST |
| UAT-05 | 成本手算 | 任取一单，按 README 公式手算：油费=km/100×油耗×油价；高速费=km×系数；其他=车辆固定杂费；空驶成本=空驶km/100×油耗×油价；净收益=运费−总成本 | 与接口 `cost` 各项一致（两位小数，误差 ≤0.01）；空驶里程口径与页面说明一致 | MUST |
| UAT-06 | 评分手算 | 任取一单，按 40/20/20/10/10 权重加权五个分项 | 加权结果（四舍五入）与 `score.total` 一致；各分项符合 `constants.ts` 档位（收益 ≥8 元/km 满分、≤0 零分；路线 100/55/25；回程 100/20；车型 100/20；时间 100/70/45/25） | MUST |
| UAT-07 | 过滤规则 | `/api/cargos?truck=…&backhaulOnly=1&maxKm=…&minPerKm=…&minNetIncome=…` 逐项构造 | 型号不符/超载/非回程/超运距/低于每公里或单趟底线的一律不出现；条件为空时不误杀 | MUST |
| UAT-08 | 排序 | `/api/cargos?sort=ai/netIncome/perKm/distance` | 各排序单调正确；`sort` 传非法值回退 `ai` 且不 500 | MUST |
| UAT-09 | 分页 | `/api/cargos?limit=5`、`?page=2&limit=5`；不传参数 | 带分页时返回 `{items,total,page,limit}`，`total`=过滤后总数；不传时仍返回数组（兼容旧客户端）；`limit>100` 被收敛 | MUST |
| UAT-10 | 接单闭环 | 接单 → 订单详情 → 逐步完成 8 步证据链 → 损耗对比 → 生成证据包 | 货源置 `taken`；订单金额与货源一致；8 步（装货称重/装车/篷布封条/途中打卡/卸货过磅/卸完/损耗对比/证据包）可完成；损耗 =（装−卸）×1000 公斤，损耗率与 `LOSS_STD` 对比给出超损结论 | MUST |
| UAT-11 | 账本与报表 | 记一笔（含 km）→ `/api/books` → `/api/export/books.csv` → `/api/export/books.html` | 月度汇总 = 运费−油费−高速−其他；每公里收益优先用真实 km；CSV 首字符为 BOM（65279）、Excel 打开中文正常；HTML 报表可打印/存 PDF | MUST |
| UAT-12 | 登录与锁定 | `POST /api/auth/register`（弱密码 `abcdef`）→ 强密码 `abc123` → `login` → 带 token 访问 → 连续 5 次错密码 → 第 6 次用对密码 → `logout` 后继续用旧 token | 弱密码 400；注册 201（不返回 token）；登录 200 返回 49 字符 token；带 token 访问 200；5 次错密 401；第 6 次 423 且 `waitSeconds≈600`；登出 200，旧 token 401 | MUST |
| UAT-13 | 降级不许 5xx | ① 不配 `DEEPSEEK_API_KEY` ② 不配 `AMAP_KEY` ③ 人为让 LLM 失败/超时 ④ 触发限流 | 无 key 用规则引擎、无高德用 Mock；失败/超时回退规则引擎；限流命中返回 200 + `limited:true`（不是 429/5xx）；页面任何路径不白屏 | MUST |
| UAT-14 | 实时推送 | `PERSIST=sqlite` 启动后开 `/api/events`（SSE）或 `/api/ws`（WS，`{type:'subscribe'}`） | 能收到 `new-cargo`/匹配回程提醒；断开后重连不崩；Mock 模式下 WS 不启动且接口有明确提示 | SHOULD |
| UAT-15 | 前端移动端 | 390×844 视口打开首页/找货/AI 助手/订单/我的/账本/信用页 | 无横向滚动；底部 5 个主 Tab 可切换；Loading / Empty / Error 三态齐全；金额只来自接口、前端不重算 | MUST |
| UAT-16 | 错误契约 | `POST /api/assistant {}`、`GET /api/cargos/NOPE` | 400 `{error}`、404 `{"error":"货源不存在"}`；错误响应统一 `{error}`，不泄露堆栈 | MUST |
| UAT-17 | 演示入口 | `web/dist` 存在时访问 `http://localhost:3000/`；双击 `start.ps1` / `start-public.cmd` | 页面由后端托管可打开；启动日志显示数据模式与 AI 引擎；README 截图与真实实例一致 | SHOULD |

## 4. 非功能验收

### 4.1 性能（基线见 §9；本机、Mock + 规则引擎、空载）

| 项 | 通过判定（MUST） |
| --- | --- |
| 冷启动 | `npm start` 后 **≤5s** `/api/health` 返回 200（基线 1.23s） |

### 4.2 安全（MUST）

- 密钥只来自环境变量：`git grep -nE "sk-[A-Za-z0-9]{10,}"` 无命中；`.env` 被 gitignore；仓库只有 `.env.example`。
- 密码 scrypt + 盐 + 恒时比较；禁止明文/可逆存储。
- `AUTH_REQUIRED=1` 时白名单（health/register/login/sms/events）之外无 token 一律 401；登录锁定 423；登出后 token 失效 401（已实测，§9）。
- `/api/assistant` 在配真实 LLM 时启用成本闸门（默认 5 次/分/IP、200 次/日），命中回退规则引擎并带 `X-RateLimit-Remaining`，不 5xx。
- 生产部署 `AUTH_REQUIRED=1`（docker-compose 默认值）且使用强密码；demo 链接公开前先确认限流生效。

### 4.3 数据与持久化（MUST）

- `PERSIST=sqlite`（或 `PERSIST=1`）重启后车辆/偏好/订单/账本不丢；`DATA_DIR` 生效。
- 多司机：数据按司机隔离；切换司机不串数据。
- `node:sqlite` 能力由 `npm run test:sqlite` 保障（3/3）。
- `PERSIST=json` 兼容旧数据；`data/` 不进 git。

### 4.4 部署（上线前 MUST；本机无 Docker 时在服务器执行）

- `docker build -t freight-radar .` 成功；`docker compose up -d --build` 后 `/api/health` 200、首页可打开。
- 公网：HTTPS（`deploy/nginx.conf.example` / `deploy/https-setup.sh`）、`AUTH_REQUIRED=1`、密钥只放服务器环境变量、`deploy/免责声明.txt` 随包。
- 局域网方案（`deploy/局域网使用方案.md`）可用；`start-public.ps1` 隧道启动器能起服务。
- 回滚：保留上一版镜像/commit；`data` 卷有备份方式。

### 4.5 可维护性（SHOULD）

- README 的 API 表、测试表、环境变量、模型名与实现一致；AGENTS.md / 本文件与现状一致。
- 源码无遗留 `TODO` / `FIXME` / `console.log` 调试残留（限流/日志开关除外）。
- `git status` 干净或已说明预期改动；无未跟踪构建产物（`dist/`、`web/dist/`、`*.tsbuildinfo` 已忽略）。

## 7. 明确不验收项（演示边界）

判定规则：这些能力缺失不算验收失败；但若 README/UI/演示话术把它们说成「已接入」，按 §8 第 10 条处理。

## 8. 一票否决清单（命中任一 = 不通过）

1. LLM 参与或改写金额、净收益、评分、排序（代码审查 + AI-01/02）。
2. `tsc` / `npm test` / 构建任一红；或测试数量下降且未说明。
3. 密钥、`.env`、token 进入 git（含历史提交）。
4. 成本/评分/排序语义变更后，UAT-05/06 手算不符或缺少对应测试。
5. AI 解释里出现 `cost`/`score` 之外的数字，或编造货源（UAT 抽查）。
6. 外部依赖失败时接口 5xx / 页面白屏（无降级）。
7. `AUTH_REQUIRED=1` 的生产配置下，白名单外可无 token 访问业务数据。
8. 未带免责声明就公网发布。
9. 文档与实现不一致导致 `tests/docs.test.ts` 红。
10. 宣称已接入真实服务（货源/短信/支付等）而实际是 Mock/演示。
11. 推送后 `gitee/main` 哈希 ≠ 本地 HEAD（只报 commit hash 不算交付完成）。
